CSS Measuring Units

Code Log 2: CSS Measuring Units (DTC 355)

Absolute vs. Relative CSS Length Units

CSS length units fall into two big categories: absolute and relative. Absolute units are fixed measurements (like inches or points), meaning they don’t change based on screen size or the user’s settings. In theory, that sounds consistent, but on modern screens it can be misleading because different devices have different pixel densities. Absolute units are usually better for print-style layouts.

Relative units are based on something else, like the font size of the element, the root font size, or the viewport size (the visible area of the browser window). Relative units are often more flexible and accessible because they adapt to different screens and user preferences (like zoom or larger default text).

1) px and pt

px (pixels) is the most common unit you’ll see. In modern CSS, a “pixel” is usually a CSS pixel (not always a literal hardware pixel), so it stays visually consistent across devices. px is great for small, precise adjustments (borders, shadows, tiny spacing), but it’s not always ideal for typography if you want text to scale nicely for accessibility.

pt (points) is traditionally a print unit (1pt = 1/72 of an inch). It can work on screens, but it’s mainly meant for print styling. Using pt for web layout is kind of like using a ruler to measure Wi-Fi speed: possible, but weird. 

/* px vs pt example */
.box {
  border: 2px solid #333;     /* px works well for borders */
  padding: 16px;              /* predictable spacing */
}

.printy-text {
  font-size: 12pt;            /* more "print" oriented */
}

2) em and rem

em is relative to the font size of the element (or its parent, depending on what you’re sizing). If an element has a font size of 20px, then 1em = 20px for that element. The tricky part is em can “compound” when nested, because child elements inherit and multiply off the parent’s size.

rem stands for “root em” and is relative to the root element font size (usually the <html> tag). rem is often easier for consistent sizing across a site because it doesn’t compound the same way em does. 

/* em vs rem example */
html {
  font-size: 16px;  /* root size */
}

.card {
  font-size: 20px;
  padding: 1em;     /* 1em = 20px inside .card */
}

h2 {
  font-size: 2rem;  /* 2rem = 32px everywhere (if html is 16px) */
}
Quick rule: rem = consistent site-wide scaling, em = scaling that follows the current element.

3) vw and vh

vw means “viewport width” and vh means “viewport height.” 1vw = 1% of the browser window’s width, and 1vh = 1% of the browser window’s height. These are useful for layouts that need to scale with the screen, like full-screen sections or responsive text.

One warning: viewport units can behave a little weird on mobile browsers because the visible area changes when the address bar shows/hides. Still, they’re super useful when you want elements sized directly to the screen. 

/* vw/vh example */
.hero {
  height: 80vh;     /* takes 80% of the screen height */
  padding: 4vw;     /* padding scales with screen width */
}

.big-title {
  font-size: 6vw;   /* text scales with the window width */
}

Mini demo idea: Resize your browser window and imagine how vh and vw would scale.

Viewport units are basically: “make it respond to the screen, not my feelings.”

Wrap-up

Absolute units (like pt) try to stay fixed, while relative units (like em, rem, vw, vh) adapt to text settings and screen size. For most modern web design, relative units are usually the safer choice because they scale better across devices and are more user-friendly.
