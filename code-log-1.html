HTML Semantic Tags

This code log is about semantic vs non-semantic HTML tags and why semantic tags are usually the better move.

Non-semantic vs semantic tags

Non-semantic tags don’t really tell you what the content is. They’re basically just containers. The main ones are <div> and <span>. If you look at a page made with a bunch of divs, you can’t easily tell what each part is supposed to be.

Semantic tags actually explain what the content is meant to be. Stuff like <header>, <nav>, <main>, <section>, <article>, and <footer> makes the structure way clearer.

Why semantic tags are useful

  • Cleaner code: It’s easier to read and you can tell what’s going on faster.
  • Accessibility: Screen readers understand the layout better, so it helps users.
  • SEO: Search engines can better understand your page (usually a good thing).

Quick example

This is a basic layout using semantic tags:

<header>Site title</header>
<nav>Links go here</nav>


<main>
<section>
<h2>A section title</h2>
<p>Some content.</p>
</section>
</main>


<footer>Footer stuff</footer>
